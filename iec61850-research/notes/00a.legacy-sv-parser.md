# Transitional Phase: IEC 61850-9-2LE Sampled Value Analysis

**Status:** Transitional Research
**Protocol:** IEC 61850-9-2LE

**Traffic Type:** Sampled Values (SV)

**Transport:** Layer 2 Ethernet

**EtherType:** `0x88BA`

**Reference Capture:** `Sample240.pcap`

**Reference Tool:** `Template_SV_viewer_rev4p0.xlsm`

**Implementation:** Native Python parser and visualization pipeline

---

## 1. Objective

This transitional phase was conducted before beginning the formal IEC 61850 security research.

The objective was to establish a working understanding of IEC 61850-9-2LE Sampled Value traffic by:

* examining a historical SV visualization tool used during UCA conformance-testing work;
* analyzing the supplied `Sample240.pcap` capture;
* independently implementing native Python parsing of the relevant SV structure;
* extracting the 9-2LE fixed dataset;
* decoding measurement and quality fields;
* tracking `smpCnt` continuity;
* reconstructing the sampled measurements as time-series waveforms; and
* establishing a baseline for subsequent IEC 61850 security experiments.

No malicious packet injection was performed during this phase. The attack scenarios described later are therefore analytical targets rather than experimentally validated attack techniques.

---

# 2. Research Context

This phase originated from technical guidance provided by Bruce Muschlitz, a former participant in UCA conformance testing. Muschlitz described the use of manual PCAP inspection during device conformance testing and provided two reference artifacts:

```text
Template_SV_viewer_rev4p0.xlsm
Sample240.pcap
```

The spreadsheet was developed to visualize IEC 61850-9-2LE Sampled Value streams. According to the supplied documentation, the tool supports 9-2LE captures using both 80 and 256 samples per cycle and handles VLAN-tagged and untagged frames. The supplied capture was used as the baseline for an independent Python implementation.

The purpose of this work was not to reproduce the original Excel implementation. The objective was to understand the packet structure and reproduce the relevant analysis path using a lightweight native parser.

---

# 3. Protocol Scope

IEC 61850-9-2 defines Sampled Value communication for process-bus applications. The 9-2LE implementation examined in this phase uses a fixed dataset containing eight measurement channels.

The traffic is transmitted directly over Ethernet.

```text
Ethernet
    │
    ├── Optional 802.1Q VLAN
    │
    └── EtherType 0x88BA
            │
            ▼
          SV APDU
            │
            ▼
           ASDU
            │
            ├── svID
            ├── smpCnt
            ├── confRev
            ├── smpSynch
            └── seqData
                    │
                    ▼
              Fixed dataset
```

The direct Layer 2 transport differentiates SV traffic from protocols that rely on TCP or UDP transport.

# 4. Capture Analysis Method

The analysis pipeline was implemented in Python and operated directly on the PCAP data.

The processing sequence was:

```text
PCAP
 │
 ▼
Ethernet frame
 │
 ▼
VLAN detection
 │
 ▼
SV EtherType identification
 │
 ▼
SV APDU
 │
 ▼
ASDU
 │
 ▼
seqData extraction
 │
 ▼
9-2LE fixed dataset
 │
 ├── Measurement values
 └── Quality fields
```

Two outputs were generated:

1. a terminal-based frame ledger;
2. a time-series visualization of the decoded measurements.

The terminal output was used to inspect individual frame properties, while the waveform representation was used to examine temporal and phase relationships.

---

# 5. Ethernet and VLAN Handling

The parser identifies SV traffic using:

```text
EtherType: 0x88BA
```

For VLAN-tagged frames, the IEEE 802.1Q header is traversed before processing the SV payload.

This allows the same parsing path to handle:

```text
Untagged SV
Ethernet → 0x88BA → SV

Tagged SV
Ethernet → 802.1Q → 0x88BA → SV
```

VLAN presence was retained as a property in the terminal frame ledger.

---

# 6. ASN.1 BER Structure

The SV payload uses ASN.1 Basic Encoding Rules (BER). The parser locates the relevant ASDU fields and extracts the `seqData` component containing the serialized measurement dataset.

The relevant processing path is:

```text
SV APDU
    ↓
ASDU
    ↓
seqData
    ↓
Fixed dataset
```

For the 9-2LE dataset examined here, the serialized measurement section is 64 bytes. The parser therefore verifies the expected dataset structure before decoding the individual channels.

---

# 7. 9-2LE Fixed Dataset

The dataset contains eight channels:

```text
Ia
Ib
Ic
In
Va
Vb
Vc
Vn
```

Each channel occupies eight bytes:

```text
4 bytes  → measurement value
4 bytes  → quality
```

The complete dataset is therefore:

```text
64 bytes = 8 channels × 8 bytes
```

The layout used by the parser is:

```text
Offset       Field

00–03        Ia value
04–07        Ia quality

08–11        Ib value
12–15        Ib quality

16–19        Ic value
20–23        Ic quality

24–27        In value
28–31        In quality

32–35        Va value
36–39        Va quality

40–43        Vb value
44–47        Vb quality

48–51        Vc value
52–55        Vc quality

56–59        Vn value
60–63        Vn quality
```

The eight value/quality pairs can be decoded using the following big-endian structure:

```python
>iIiIiIiIiIiIiIiI
```

where:

```text
i = signed 32-bit measurement value
I = unsigned 32-bit quality field
```

# 8. Sample Counter

The `smpCnt` field was extracted for every successfully parsed SV frame.

For an 80-samples-per-cycle stream operating at 60 Hz:

```text
80 samples/cycle × 60 cycles/second
= 4800 samples/second
```

This corresponds to a nominal counter range of:`0–4799` within a one-second interval. The counter was therefore retained as part of the frame ledger and used when evaluating sample continuity. The counter was not treated as an independent measurement-integrity mechanism.

---

# 9. Waveform Reconstruction

The decoded measurement values were accumulated into time-series arrays.

The resulting data was plotted as continuous waveforms for:

```text
Ia
Ib
Ic
In

Va
Vb
Vc
Vn
```

The purpose of the visualization was to evaluate characteristics that are difficult to identify from a packet table, including: waveform continuity; amplitude consistency; periodicity; phase relationship; frequency; neutral-channel behavior; and abrupt changes between adjacent samples. The visualization therefore operates as a second analytical layer over the packet dissection.

---

# 10. Baseline Capture: Sample240.pcap

The supplied `Sample240.pcap` was used as the reference capture.

The parser extracted:

```text
239 valid 9-2LE frames
```

The capture represents approximately three cycles of an 80-samples-per-cycle stream. The resulting dataset was sufficient to reconstruct the three-phase current and voltage channels and inspect their waveform behavior.

The reconstructed signals exhibited:

* continuous periodic behavior;
* stable relative amplitudes;
* recognizable three-phase separation;
* expected power-system frequency characteristics;
* observable neutral-channel behavior; and
* populated quality fields.

The analysis therefore established a baseline representation of the supplied capture. The capture should not be interpreted as mathematically perfect or as proof of physical-system integrity. The result establishes the behavior observed in the supplied PCAP through the implemented parser.

---

# 11. Observed Three-Phase Behavior

The reconstructed current and voltage channels displayed the expected three-phase waveform structure. The three phase channels were separated in time and maintained consistent periodic relationships throughout the analyzed capture.

The observed behavior provides a useful baseline for future comparisons involving:

```text
Amplitude changes
Phase displacement
Frequency changes
Waveform discontinuity
Channel substitution
```

The baseline is particularly relevant because abnormal telemetry cannot be evaluated without first establishing the normal characteristics of the source stream.

---

# 12. Neutral Channel Behavior

The neutral channels were retained in the visualization rather than discarded as secondary measurements. This was motivated in part by the historical observations provided with the reference material. A neutral measurement may represent an actual measured quantity or, depending on implementation, a quantity derived from the phase measurements. This distinction affects how the resulting waveform should be interpreted.

The transitional analysis therefore treats the neutral channel as an additional measurement requiring contextual interpretation rather than assuming that any observed waveform represents a directly measured physical quantity.

---

# 13. Historical 9-2LE Dataset Considerations

The historical material provided an additional perspective on the 9-2LE dataset design.

One previously proposed extension involved adding a `derived` indication to the quality information to distinguish neutral quantities that were calculated from the three phase measurements from quantities obtained directly from an instrument transformer.

This extension was not retained in the final implementation described by the supplied historical account. It is therefore treated here as **historical design information**, not as a standardized quality flag used by the parser. A second design consideration involved fixed datasets intended to simplify interoperability between merging units and subscribers. The historical discussion also highlighted the distinction between 80 and 256 samples per cycle and the resulting dataset interpretation requirements. These considerations provide context for why fixed dataset structure is relevant to both conformance testing and packet-level analysis.

# 14. Security-Relevant Analysis

The transitional parser was not developed as a validated intrusion-detection system. However, the reconstructed telemetry provides a basis for investigating several classes of anomalous SV behavior.

## 14.1 Counter Manipulation and Replay

Potential indicators include:

```text
Repeated smpCnt values
Unexpected counter transitions
Repeated measurement sequences
Temporal discontinuities
```

Counter analysis can therefore provide evidence of replay or sequence manipulation. However, additional contextual analysis would be required to distinguish malicious replay from legitimate synchronization or capture artifacts.

---

## 14.2 Measurement Suppression

A manipulated dataset containing zero or near-zero measurements could appear as:

```text
Normal waveform
      ↓
Abrupt amplitude reduction
      ↓
Flat or near-flat signal
```

This behavior could be relevant to attacks attempting to suppress measurement information. The same observation could also result from legitimate equipment or measurement faults. Waveform behavior alone is therefore insufficient to attribute causality.

---

## 14.3 Phase Manipulation

Manipulating individual phase values could alter the expected relationship between:

```text
Ia / Ib / Ic
```

or:

```text
Va / Vb / Vc
```

Potential indicators include:

* abnormal phase displacement;
* unexpected amplitude imbalance;
* discontinuities;
* altered waveform relationships.

The nominal three-phase relationship should be treated as a baseline rather than a strict mathematical invariant because real systems exhibit imbalance, harmonics, transients, and measurement error.

---

## 14.4 Quality Manipulation

The quality field provides logical metadata associated with each measurement.

A manipulated quality state could therefore create a discrepancy between:

```text
Measurement waveform
        │
        └── Appears physically normal

Quality metadata
        │
        └── Indicates abnormal state
```

This creates a second potential analysis path in which the numerical measurement and its associated quality metadata are evaluated together.

---

# 15. Protocol Integrity vs. Measurement Integrity

The transitional experiment identified two separate validation domains.

### Protocol integrity

```text
EtherType
VLAN
BER structure
ASDU structure
Dataset length
smpCnt
Quality field
```

### Measurement integrity

```text
Waveform continuity
Amplitude
Frequency
Phase relationship
Channel consistency
Neutral behavior
```

The two domains provide different information. A structurally valid SV frame can still carry a measurement that is inconsistent with the surrounding telemetry. Conversely, an unusual waveform does not necessarily indicate a malformed or malicious packet. This distinction will be retained as a working analytical principle for the formal IEC 61850 research.

---

# 16. Limitations

The transitional phase has several explicit limitations.

### No malicious traffic was generated

Replay, suppression, phase manipulation, and quality manipulation were not experimentally injected into the reference capture. The associated sections therefore describe analytical hypotheses rather than demonstrated attack results.

### Single reference capture

The baseline analysis was performed against `Sample240.pcap`. The capture does not establish the full range of legitimate behavior across different merging units, sampling configurations, electrical conditions, or vendors.

### 239 successfully parsed frames

The implementation extracted 239 valid frames from the supplied capture. The result should not be described as 240 successfully parsed frames or as exactly three complete cycles without separately accounting for the unparsed/missing frame.

### Physical interpretation requires domain context

Waveform anomalies cannot independently establish malicious activity. Equipment failures, configuration errors, synchronization problems, sensor behavior, and capture artifacts may produce similar observations.

# 17. Transitional Findings

The completed phase produced the following findings:

1. **9-2LE Sampled Value traffic can be analyzed directly from Layer 2 Ethernet captures without relying on a high-level protocol framework.**

2. **The fixed 9-2LE dataset provides a deterministic structure suitable for lightweight native parsing.**

3. **The eight measurement channels can be reconstructed directly from the serialized 64-byte dataset.**

4. **`smpCnt` provides a useful temporal reference for evaluating sample continuity.**

5. **Waveform reconstruction exposes characteristics that are difficult to evaluate from tabular packet fields alone.**

6. **Three-phase relationships provide a useful baseline for subsequent measurement-integrity analysis.**

7. **Neutral-channel interpretation requires awareness of whether the measurement is directly acquired or derived.**

8. **Protocol-level validity and physical measurement plausibility must be treated as separate analytical dimensions.**

9. **The reference capture establishes a baseline but does not constitute experimental validation of malicious manipulation.**
